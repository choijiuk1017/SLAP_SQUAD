# SLAP SQUAD

Unity 기반으로 개발한 3D PvP 멀티플레이 게임입니다.

플레이어는 서로 다른 무기를 사용하는 캐릭터를 선택하고, 맵의 오브젝트와 풍선을 활용하며 다른 플레이어와 대전합니다.

서버 프로그래머와 협업하여 캐릭터 조작과 전투, 로그인·로비·방 입장·게임 진행 UI, 패킷 송수신 및 원격 플레이어 동기화를 포함한 클라이언트 개발을 담당했습니다.

## 게임 흐름

```text
Login
  ↓
Lobby
  ↓
Room
  ↓
Game
  ↓
Result
  ↓
Lobby
```

### Login

서버 접속과 사용자 인증을 처리하고, 로그인 성공 시 로비로 이동합니다.

### Lobby

접속 중인 사용자와 생성된 방 정보를 서버로부터 받아 화면에 표시합니다.

로비에서는 다음 기능을 제공합니다.

- 사용자 목록 확인
- 로비 채팅
- 방 생성
- 방 검색 및 입장
- 로그아웃
- 사용자 정보 확인

### Room

입장한 플레이어의 정보를 관리하고 게임 시작 전 상태를 동기화합니다.

방장과 일반 사용자의 상태를 구분하고, 플레이어 입장·퇴장 및 게임 시작 요청을 처리합니다.

### Game

서버로부터 전달받은 게임 정보를 기반으로 로컬 플레이어와 원격 플레이어를 구성합니다.

게임 중에는 다음 정보를 송수신합니다.

- 플레이어 이동
- 회전 및 애니메이션
- 공격 요청
- 공격 결과
- 피격 및 체력
- 사망 상태
- 게임 진행 상태
- 게임 종료 및 보상

## 주요 구현 기능

### 1. 플레이어 조작

`LocalPlayerController`에서 로컬 플레이어의 입력과 이동을 처리합니다.

- 키보드 입력을 이용한 이동
- 캐릭터 방향 및 회전 처리
- 공격 입력
- 애니메이션 상태 변경
- 캐릭터 상태에 따른 입력 제한
- 로컬 플레이어와 원격 플레이어 처리 분리

로컬 입력으로 결정된 행동을 즉시 화면에 반영하고, 필요한 정보를 서버에 전송하도록 구성했습니다.

### 2. 캐릭터 시스템

`CharacterSystem`에서 게임에 참여한 캐릭터의 생성과 상태를 관리합니다.

캐릭터 데이터와 선택 정보를 기준으로 각 플레이어에게 맞는 모델, 애니메이션 및 무기 시스템을 구성합니다.

### 3. 무기 시스템

`WeaponSystem`을 중심으로 캐릭터별 무기 공격을 관리합니다.

프로젝트에는 다음과 같은 개별 무기 스크립트가 구성되어 있습니다.

| 무기 스크립트 | 역할 |
| --- | --- |
| `Sword` | 검 기반 근거리 공격 |
| `Mace` | 둔기 기반 근거리 공격 |
| `Pitchfork` | 긴 공격 범위를 가진 근거리 공격 |
| `Arrow` | 투사체 기반 원거리 공격 |
| `Laser` | 레이저 기반 원거리 공격 |
| `Spell` | 마법 공격 |
| `Melody` | 캐릭터 고유 공격 처리 |

각 무기의 공격 방식을 개별 스크립트로 분리하여 캐릭터별 공격 특성을 독립적으로 관리하도록 구성했습니다.

### 4. 풍선 시스템

`BalloonSystem`에서 게임의 핵심 오브젝트인 풍선과 관련된 상태를 관리합니다.

풍선 획득과 사용, 캐릭터 상태 변화 및 서버 메시지에 따른 결과 반영을 게임 시스템과 연동했습니다.

### 5. 맵 시스템

`MapSystem`에서 맵 오브젝트와 게임 환경을 관리합니다.

플레이어가 선택되거나 서버로부터 전달받은 맵 정보에 따라 게임 환경을 구성하고, 맵에서 발생하는 상호작용을 처리합니다.

### 6. 이모티콘 시스템

`EmoticonSystem`을 통해 플레이어가 게임 중 이모티콘을 사용할 수 있도록 구현했습니다.

이모티콘 사용 정보를 다른 클라이언트와 공유하여 동일한 시각적 반응을 확인할 수 있도록 구성했습니다.

### 7. 게임 진행 관리

`GameSystem`에서 게임의 전체 상태와 진행 흐름을 관리합니다.

- 플레이어 정보 초기화
- 게임 시작
- 게임 진행 상태 갱신
- 플레이어 탈락 및 사망 처리
- 게임 종료
- 보상 정보 처리
- 결과 화면 전환

## 네트워크 처리 구조

### 전체 구조

```text
Server
  ↓
NetworkConnector
  ↓
Message Type Parsing
  ↓
Registered IMessageHandler
  ↓
Login / Lobby / Room / Game Receiver
  ↓
Game Logic & UI
```

### NetworkConnector

`NetworkConnector`에서 서버 연결과 메시지 송수신을 담당합니다.

수신한 데이터는 메시지 타입을 기준으로 파싱한 뒤, 해당 메시지를 구독한 Handler에 전달합니다.

네트워크 연결부가 특정 게임 기능을 직접 처리하지 않도록 구성하여 네트워크 계층과 게임 로직의 결합을 줄였습니다.

### IMessageHandler

기능별 Receiver는 `IMessageHandler` 인터페이스를 구현합니다.

```text
IMessageHandler
 ├─ Login Receiver
 ├─ Lobby Receiver
 ├─ Room Receiver
 └─ Game Receiver
```

각 Receiver는 필요한 메시지만 구독하고, 해당 메시지를 수신했을 때 자신의 기능을 처리합니다.

이를 통해 새로운 메시지나 기능이 추가될 때 `NetworkConnector` 전체를 수정하지 않고 새로운 Handler를 등록할 수 있도록 구성했습니다.

### 메시지 처리 과정

```text
1. 서버에서 메시지 수신
2. 메시지 타입 확인
3. Command 단위 데이터 파싱
4. 등록된 Handler 검색
5. 기능별 Receiver에 메시지 전달
6. 게임 상태와 UI 갱신
```

### 기능별 송수신 분리

로그인, 로비 및 방 시스템은 Sender와 Receiver를 분리했습니다.

예를 들어 로비는 다음과 같이 구성되어 있습니다.

- `LobbySender`
- `LobbyReceiver`
- `LobbySystem`
- `LobbyRoom`
- `LobbyUserList`
- `LobbyChat`

Sender는 서버 요청을 담당하고 Receiver는 서버 응답을 처리하며, System은 수신한 결과를 실제 UI와 게임 상태에 반영합니다.

## 전투 시스템

### 공격 처리 흐름

```text
Player Input
  ↓
LocalPlayerController
  ↓
WeaponSystem
  ↓
Weapon Animation
  ↓
Attack Packet
  ↓
Server Validation
  ↓
Attack Result Packet
  ↓
Damage & Visual Feedback
```

로컬 플레이어가 공격하면 선택된 캐릭터와 무기에 맞는 공격 애니메이션을 실행하고 서버에 공격 정보를 전송합니다.

서버로부터 공격 결과를 수신하면 대상 플레이어에게 피격 및 체력 변화를 적용합니다.

### 원격 플레이어 공격

원격 플레이어의 공격 패킷을 수신하면 공격 캐릭터와 무기 정보를 기준으로 해당 공격 애니메이션과 공격 처리를 재생합니다.

로컬 플레이어와 원격 플레이어의 입력 처리 경로를 분리하되, 동일한 무기 시스템을 활용하도록 구성했습니다.
